# 修改、编剧把控与验收

作者描述“写不下去/中段拖/没有感觉”时，先用 [卡稿诊断](writer-collaboration.md#卡点诊断必须回到正文) 找到实际阻力，再执行下面的修订链路。新路线要落到授权范围的正文，不以问题表代替改写。

完整创作自审或“逻辑都对但不好看”的改稿，先用 [故事质量审读](story-review.md) 区分人物牵引、期待、关系、场面和终场回报，确定本轮最值得改的问题。严重因果/现实机制断裂先修；其余创作判断以作者目的和正文效果取舍，不以发现问题数量或全表通过衡量质量。

作者明确批评台词“没人味/跨服聊天/割裂/正确废话”时，直接用 [对白修订](dialogue.md#修订找到第一处没接上的地方) 定位第一处没接上的触发与回应，交实际整段替换。先检查人物听见了什么、据此误解/回避/改变了什么；有意误会与角色犯错可以保留，不能用更漂亮的措辞遮掉知情或情绪断裂。

## 从作者意见到有效新稿

1. **锚定版本与范围**：记录基准稿、作者回传稿和意见来源。先对照实际增删与显式要求，已撤回的旧意见不再执行；回传稿覆盖哪些集/场就记录哪些，不能凭未见文件声称整剧已核。
2. **明确改动目的**：将“更狠/不够爽/太中式/台词假/中段拖”拆成可检查的场景问题；能从现稿与既有口味判断时直接给方案并改稿，不要求作者先写完整修改说明。
3. **区分必做与建议**：明确指令优先落实；对未锁定部分提出少量更优解，说明收益、代价和影响范围。不要用自己的替代方案悄悄顶掉作者已明确的选择。
4. **检查依赖**：先看连续控制文档，定位直接受影响场及前置伏笔、人物知情、道具、关系、后续回收、开场与钩子，再改实际正文。
5. **按口味执行**：风格决定表达强度、节奏与人物尺度，不取代因果和事实。保留作者喜欢的独特点，避免每轮都把高情绪写法润成同一种克制声音。
6. **复检并交付**：意见逐条给出采纳/部分采纳/保留及理由、修改位置和结果；重新核对语言阶段、篇幅与连续性。交付净稿和必要变更说明，不能只有问题表没有改写正文。

回传中文稿后按 [语言阶段](chinese-to-english.md) 进入英文重写；用户只要求继续中文修改则保持中文。中文新改动使关联英文场次成为待同步，不能把旧英文重新命名成已修订。

## 编剧口味记录

在项目内保存用户明确的偏好、禁区和已选样例，包括开场强度、情绪/修辞尺度、节奏、对白直接程度、幽默、人物底线、关系与结局。每项带来源/版本和适用范围。推测出的偏好标“暂定”，一次局部选择不自动升为所有项目的固定风格；也不改其它技能或全局配置。

例如作者说“更狠”，已知偏好是强对抗但主角不伤人：可以缩短主角犹豫、让拒绝带来具体损失，不能擅加人身暴力。“更地道”可重写言语策略与回应，不意味着降低情绪或加入俚语。对口味与硬约束的冲突说明具体位置，给可比较的写法。

### 用已选段落校准口味

抽象偏好反复造成分歧时，从真实意见中保存少量“认可短例 / 否定短例 / 具体原因 / 适用人物与场景 / 来源版本”。短摘足够定位即可，不复制整份作者稿；用户尚未选择的备选只标候选，不编造认可记录。

例如作者实际选择“把我的名字加回去”，否定“我要你身败名裂”，理由是需要明确夺回署名而非泛化威胁：以后处理同一人物的同类争夺，优先写具体可执行要求；这不代表作者在所有项目都排斥夸张表达。作者只说“更狠”但没有足够证据时，可以先落实一种符合已知底线的写法并说明理解，不把每句都变成选择题。

偏好冲突按范围处理：本场明确要求优先于泛泛风格记录；当前有效取舍更新旧记录；事实、同意和锁定底线仍须成立。只有新增要求确实互斥且影响重要选择时才交给作者决定，不用推测口味改写结局。示例库是项目记忆，不是训练所有作者统一说话的标准。

### 每轮修改保住什么

修前从本轮意见提取可观察结果，修后对照实际正文，同时回查少量受影响的已锁事项。例如“让对峙更强，但保留她未承诺合作”：核查新动作是否产生代价、她是否仍只同意考虑、后续有无据此当成已合作。不以“已加强”“已地道”代替证据。

每轮只汇报关键的“本轮目标与结果 / 保留的已选特点 / 联动修改 / 未决分歧”。新意见若改了旧取舍，明确记替换关系；以后回查有效决定，不把所有历史要求累加。案例失败就修正文和相关规则，不追加全项目无关的核查项。

| 作者反馈 | 优先诊断 | 执行与复查 |
|---|---|---|
| 开头抓不住人 | 3—5秒内是否有可辨认的异常/利益碰撞；关系信息是否过载 | 换成有后果的入口；重估英文时长并检查正文兑现 |
| 不够爽/不够强 | 主角是否行动、胜利是否有价值、回报是否延迟；不先假定需要更大暴力 | 改选择、对手应对和所得/所失；保留人物底线与类型尺度 |
| 太像中文台词/不自然 | 称呼、背景解释、抽象比喻、问答衔接、双方已知信息 | 按意图重建英语；核对否定/条件、责任和潜文本不变 |
| 中段拖沓 | 是否同一争夺反复回到起点、阶段目标停滞 | 合并同功能戏，增加由行动产生的新条件，更新依赖与预算 |
| 要把秘密后移/换结局 | 哪些事实、知情与行为依赖旧揭晓或终点 | 重写前后正文并更新对应英文；不只移动一句台词 |

## 更好的建议怎样交给作者

对高影响问题采用“你要达到的效果—现稿障碍—已落实的改法—一个值得考虑的替代及代价”。建议应可比较、可拍、符合已知口味；若只是措辞小修直接给最合适的一版。用户授权自由优化且未触及锁定事项时可采纳推荐方案并说明；改变锁定主题、底线或结局的方案单列，不能装作已获得认可。

意见互相冲突时给出具体冲突和推荐解法，继续无依赖部分；需要作者决定时呈现实际可审阅的新段落/备选，减少空泛确认。未采纳的意见明确解释原因，不写“全部完成”。

## 修改顺序

1. **结构与因果**：核对主线问题、欲望/阻碍/选择、阶段回报和结尾；逆读高潮依赖的铺垫，换配角视角检查动机。合并重复冲突，修复凭空线索和反复重置的误会。
2. **文化与改编**：核对事实台账和本土化决策；规则改变时连带修改角色可做的选择及结果。
3. **场景与对白**：按对白文档重写当场相互影响，再查口语、称谓、潜文本和表演节奏；每句不必推动大情节，人物、关系、情绪和节奏作用也保留。
4. **连续性与篇幅**：检查时间、伤情、服装/道具、人物知情、秘密、称呼、地名、承诺回收；重新统计真正正文与对白，复估动作时间。
5. **内容风险**：核验改动涉及的权利/内容要求；只因具体新改动触发时扩大研究。

先处理决定人物和剧情的高影响问题，再做标点和措辞。不用盲目增加反转或删掉必要情绪反应达到词数。

## 七维验收

以下检查交付是否可靠，连同白皮书W项提供创作依据；“各项有证据”不能单独证明人物难忘或情绪有效。创作审读另说明最强的具体场次、仍薄弱的体验及本轮改稿的收益/代价，不额外给一个“好故事合格分”。

| 维度 | 通过所需证据 |
|---|---|
| 选材 | 观众与情绪承诺明确；市场结论有真实地区/时间/指标或标明假设；样本分析区分观剧范围与梗概；独特戏剧引擎可持续 |
| 对白 | 当前语言的整场听与答成立，事实/情绪承接和回避可追踪；人物在具体处境中有自己的说法；英文重写保住有效作者版本及否定/条件/责任；朗读/模拟/真人状态真实 |
| 文化背景 | 地域和社群具体；影响因果的制度事实已核或标待核；没有无意混用两国制度 |
| 本土化 | 保留项和改动项清楚；关键桥段当地机制成立；原素材权利有状态；原创项目可标不适用 |
| 格式和篇幅 | 当前语言约定范围实际有正文；集场与跨批连续性清楚；已生成英文才核实W；中文量独立记录；开场3—5秒与片长估时有假设/实测状态 |
| 合规性 | 相关法域、权利与平台要求分开核验；具体风险已修改或列明残余待核项 |
| 修改 | 意见逐条闭环；修订联动到前后场次；原定主题、人物边界与结局选择可追踪 |

另对 [白皮书W01—W22](whitepaper-rules.md) 给出通过/需改/待核/不适用及集场证据。局部修改只检查相关条目，不用全套表格压过改稿本身。

极短项目可把共享同一证据的W项与七维结果合并成简表，保留各项状态和定位；已写在分集表的因果/伏笔不再全文复述。详细记录可存工作文件，对用户先呈现净稿、关键修改和待核事项，避免稿外记录淹没正文。

## 编剧把控

优先向真人编剧呈现需要其判断的具体选择，例如“主角是否愿意牺牲妹妹的信任”“结尾和解是否削弱原主题”，附当前写法、建议、备选及影响。排版、错字和已授权的连续性修复无需逐个批准。不得把AI扮演审稿者写成已请真实编剧审稿。

反馈记录：意见ID、提出者/来源、关联稿版本、意见、决定、具体修改、影响集场、复检结果。被保留的原写法有明确理由；意见冲突时说明冲突而非择一后假装全部满足。

## 定稿状态

核查已约定范围、当前语言阶段、遗漏集、重复场、未完成文本、悬念回收、适用篇幅、格式及已识别风险。中文量与英文W分开核查；正文中待写标记只是提示，语境里的正常单词不能误报成未完成。

最终给出：实际完成范围和版本、净稿、统计口径与结果、已解决的重要问题、剩余事项和责任类别。真人确认缺失标“创作稿完成，待编剧确认”；专业/发行核验未完成可单列，不伪称法律通过。用户已确认且条件满足时直接交付，不为走流程反复索取确认。

用分开的状态避免“工具通过”等于“整剧通过”：

| 检查 | 可报告的结果 |
|---|---|
| 结构解析 | 通过/需改；含集号连续性、正文存在、场景接续、格式支持范围 |
| 英文总词数 | 英文已生成才报通过/需改；未生成/未约定须注明，列目标、实际与容差；中文计量另记 |
| 英文逐集词数 | 英文已生成才检查预算与偏差，批次只判断该批；中文稿不能由此取得英文篇幅通过 |
| 创作自审 | 白皮书及七维的具体结果，模拟读稿与实际计时分开 |
| 真人编剧反馈 | 未取得/已取得待处理/已处理；记录意见来源和版本 |
| 发行与专业核验 | 已核范围、待核项或不适用；有依据才写平台批准/正式评级 |

导出另记录格式检查和实际渲染状态。工具输出的 `passed` 仅汇总机器可查的结构和已提供数字约束；`not_checked` 不可写成已满足约定。没有真人意见仍可完成授权的创作与自审。

## 修改联动实例

编剧把“妹妹复制钥匙”从第2集移到第3集揭晓：先定位这个事实被观众/各人物得知的位置，再修改第1集的可见线索、第2集基于旧信息的指责、第3集证据来源与反应，以及后续已经知道真相的对白。保留公平线索但改变其当时含义，不能只移动一句揭晓台词。复查钩子台账、知情表、道具持有、原结局与逐集预算；已确认不变的关系和底线留在修改记录中。

有真实读稿/观看反馈时，先区分不理解信息、缺少情绪理由和节奏问题；处理方法见 [单集推进](episode-craft.md#有反馈后的修改)。缺少数据时不编造留存结论。
