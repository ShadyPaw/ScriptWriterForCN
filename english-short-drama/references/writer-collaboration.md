# 构思、卡稿与写作协作

用于作者想法不完整、已有稿写不下去、要求续写/压缩或无法准确描述问题的情况。先识别现有素材与本轮范围；已有约定和口味沿用，缺口只在妨碍关键选择时才问。目标是交付作者能审阅和修改的内容，项目记录按需要保存在稿外。

## 起步与每轮交付

作者只有一句想法时，先把它发展成能判断的主角、具体冲突、观看期待和推荐方向；缺少集数、词数或平台时给标明假设的体量建议，按已授权范围试写，不让作者先填完整项目卡。作者只想讨论则交可比较的方案；请求写作、续写或改稿则交正文。会改变重要选择的缺口才提问，其余可调整项先形成可审阅内容。

默认先呈现本轮最有用的成果：选题时是推荐与差异，写作时是净稿，修改时是实际替换。随后简短说明决定、收益/代价和仍需作者选择的事项；详细计数、W项和连续性依据放在稿外文件，作者需要时提供。已有约定不重新确认，不把工作假设称为已批准。

白皮书与图片模型转成正文的办法见 [竖屏创作衔接](vertical-development.md)。作者不熟悉模型名称时，用“前段让他们相互需要，中段让合作成果反过来伤害目标”之类的白话说明取舍；除非需要讨论结构，不把五模型讲义插在净稿前。

作者只说“没感觉”时，依据现稿先定位一个最影响效果的问题并改一段；口味确实不明时给少量短而有实质区别的写法，保留同一事实供比较。实际选择再更新既有口味记录，不把每句都变成确认题，也不让作者先学会审稿术语。

续写时从有效稿的出口直接推进，简短提醒真正影响本轮的状态。交付结尾说明当前完成范围与下一个需要决定的内容即可；已授权的当前工作完成后，不擅自扩展后续集或切换语言阶段。

## 按输入选择帮助方式

| 作者当前输入 | 先解决什么 | 实际交付 |
|---|---|---|
| 只有题材、情绪或一句设定 | 欲望、对抗、持续联系与阶段变化 | 按 [故事发展](story-development.md) 给少量不同路线、明确推荐及理由；授权试写则写推荐开场，未授权整稿不自行扩整部 |
| 有人物/大纲，想写正文 | 将已选事实变成当前场争夺和选择 | 当前语言的实际集场正文，按N/篇幅及完成范围核对；只补影响因果的缺口 |
| “后面写不下去”“这一段拖” | 找到重复状态、阻力不足、秘密耗尽、主角被动或关系停滞中的真实原因 | 定位到现稿，给实质不同的继续路线、推荐一条并在授权范围内落实正文 |
| “不甜/不爽/没感觉/不像当地人” | 分开诊断关系依据、回报价值、言语策略与当地机制 | 先修导致问题的节拍，再给改写；强度和风格依有效口味，不擅改人物底线 |
| 要压缩/扩展/调整集数 | 分清重复功能与不可缺依赖 | 合并或扩展事件量，维护既有伏笔、关系与结尾；只有重新统计过的正文才计入已完成 |

选材确需当前市场依据、现实制度决定因果或英语用法存在实质不确定时再联网，优先官方作品/原声材料、主创本人及官方制度来源。一次用法困惑不扩成与改稿无关的全网报告；缺乏可访问材料时标待核，继续不依赖它的写作。

## 卡点诊断必须回到正文

读到卡点前最后一个有效变化，确定此刻谁想做什么、什么已尝试失败、下一选择为何发生不了。作者只给概要时把判断标为暂定，不声称读过不存在的前稿。可以继续独立部分，涉及未知秘密/终局则先给局部可审阅备选。

| 现象 | 检查证据 | 推荐的改动方向 |
|---|---|---|
| 连续几集都在争同一件事 | 进入/离开状态相同，解释和信息没有累积 | 兑现一项小问题，让结果改变下一目标；合并重复争吵 |
| 秘密揭晓后没戏 | 两人只等道歉，外部目标已解决 | 把真相转成责任、联盟或新选择；锁定结局不变时倒推新的代价 |
| 主角只能被救 | 关键资源/证据全由别人送来 | 用其已有能力制造一个有后果的尝试，允许失败和求助 |
| 对手不停羞辱 | 对手没有损失、筹码或策略变化 | 从其想保住的东西出发设计下一招；让其利用已经知道的信息 |
| 恋爱只有互夸/误会 | 缺少具体吸引、风险及关系状态变化 | 让两人完成一项能暴露能力/弱点的任务，再由行为改变靠近程度 |
| 每句正确，整场不动 | 发言互不回应；没有人因对方改变办法 | 先重排争夺与策略，再做英语润色，见 [类型场戏](genre-scenes.md) |

## 路线比较之后落实

较大卡点通常给二至三条因果不同的路线；已经有明确方向或只是小修时直接给最佳写法。比较每条的角色动机、所得/所失、对后续和篇幅的影响，以及是否符合作者偏好。区分“需要作者决定的锁定事项”和“已有授权的可执行优化”，不将所有选择都退回给作者。

作者说“帮我改/接着写/自由优化”时，在该范围内写出首选方案的实际正文；改到全剧结尾以外的范围不自动扩大。输出以净稿为主，少量列关键改动、剩余取舍和同步状态，不用长篇分析代替改写。

已有因果但缺少吸引力时，按 [故事质量审读](story-review.md) 找到最影响作者目的的体验缺口；人物只剩标签时按 [人物选择](story-development.md#让人物长成难以替换的选择) 发展，整场没劲则按 [场面重构](genre-scenes.md#平淡场景的重构) 改。先保住现稿独特的乐趣与口味，不因一句“不够好”就推翻作者已经喜欢的全部内容。

若建议被作者否定，记录真正被否定的原因及范围，沿有效选择继续；删除的桥段不借旧稿恢复。原有 [修订链路](revision-and-review.md) 和 [版本合并](chinese-to-english.md#部分回传与逐场合并) 仍是唯一反馈/版本记录，不再创建平行审批流程。

## 自查是否真正帮到了写作

检查交付是否完成作者这轮所需的下一步：想选方向时能比较，想续写时有正文，想改戏时有实际替换，想定稿时有完整范围和核查。不给市场成功或母语自然度无依据的总分。完整项目的自审、模拟作者意见、真人意见与受众效果分别记录；测试项目不能冒充作者的真实作品或反馈。
